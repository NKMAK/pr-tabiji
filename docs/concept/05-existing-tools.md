# 05. 既存ツールの調査と差別化

調査日: 2026-11-23。各ツールの公開ドキュメント・紹介ページに基づく。URLは [references.md](references.md) を参照。

## 結論

PRを読む順番に並べ替えて解説するツールは、すでに数多くある。どれも「まとめる・並べる・要約する」が中心。
pr-tabiji の差別化は、**具体的なデータを流して値の変化を追うこと**、**コードより一段抽象度の高い日本語を並べること**、そして**情報を絞るという思想**にある。

## 各ツールの中身

### CodeRabbit（Change Stack）
- レビュー専用の画面。左に目次、右に中身の2ペイン構成。
- 概要ページ: 層の数、ファイル数、追加・削除行数、重大度ごとの指摘数。各層の要約。
- 層: 契約・実装・テストのように関連ファイルをまとめたもの。変更を作った順に並ぶ。
- 層を開くと通常のdiffが出て、AIの指摘が該当行の下に表示される。範囲を選んでチャットで質問できる。

### Sourcegraph（Diff Tour）
- 重要なファイルを先頭に置き、関連ファイルをセクションにまとめる。
- 全体・セクション・ファイルごとに説明を付ける、目次付きの読み物。

### diff-tour（OSS）
- ターミナルから起動し、矢印キーで1ステップずつ進む。
- 各ステップ: 変更の目的、次に読むべきファイル（変更されていないがリスクがあるファイルも含む）、シニア視点の問い（「2回実行されたら？」など）。
- 問いの答えは伏せてあり、自分で考えてから見る、学習寄りの作り。
- Claude Code などの既存のAI CLIを使って生成する。
- 作者自身が、データがどう保存されてどうつながるかはまだ説明できていないと述べている。

### balade（OSS）
- AIが書いたMarkdownのウォークスルーを、レビュー用の画面で表示する。
- 構成: 概要 → セクションごとの解説文と該当コード → Mermaidの図 → 最後に全ファイルのdiff。
- コード参照に、その範囲の1行目と一致すべき文字列を書く。一致しなければ検証で落ちる（解説とコードのズレを防ぐ仕組み）。

### その他
- prtour（OSS）: 読む順の章立てと、行に紐づくノート。レビュー不要な部分を隠す。
- Graphite Code Tours: PRを案内付きのウォークスルーにする。
- GuidePR、PR Explainer（音声で解説）、PR Lens（図を自動生成）など。

## 現状の実務ツールとの比較

| 要素 | 既存ツール |
|---|---|
| 3行の概要 | どれにもある |
| アーキテクチャ・データフロー図 | 一部ある（baladeのMermaidなど） |
| エンドポイント → DTO → ドメイン → リポジトリの順で読む | 似たものはある。ただし既存は「作った順」で、実行時の流れの順ではない |
| コードと日本語の類似コードを並べる | 見当たらない |
| この値が入ったらどうなるかを見る | 見当たらない |

## 思想の違い

| | 既存ツール | pr-tabiji |
|---|---|---|
| 方向 | AIに説明を足させる（要約、指摘、問い、チャット） | 情報を絞り、出す順番を決める |
| 読む軸 | ファイルのまとまり、作った順 | データの旅（実行時の流れ） |
| 具体 | diffそのもの | diff ＋ 値の変化 |
| AIの立場 | 解説者・レビュアー | 案内人（分からないことは「要確認」） |

## 名前について

- 既存ツールは tour、散歩（balade）など「ツアー」系の名前が多い。埋もれないよう避けた。
- `pr-tabiji` に決定。npm と GitHub で同名のものがないことを確認済み（2026-11-23）。
- `tabiji` 単体は npm に別パッケージがあり、GitHub でも旅行アプリなどで使われているため不採用。

## 取り入れる候補

- 解説とコードの一致を検証する仕組み（balade）
- 既存のAI CLIを使って生成する方式（diff-tour）
