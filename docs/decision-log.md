## 採用しなかったこと

| 案 | 理由 |
|---|---|
| 要所だけ検証し、内部実装は流し読みする | 理解していないコードをマージすべきではない |
| 出す情報量に固定の上限を設ける（要点は3つまで、など） | 件数で決める必要はない。判断に必要かどうかで絞る |
| 理由に必ず出典を表示する | ノイズになる。生成時のルールとしてのみ残す |
| 層ごとの説明と処理単位の説明を両方読む構成 | 重複の可能性がある |
| 日本語の類似コードを行ごとの翻訳として書く | 同じ内容の言い換えで、読む量が倍になる。意味を書く方針に変更 |
| 「問いとして返す」という表現 | 意味が伝わりにくい。「要確認として示す」に言い換えた |
| テストを先に読むことを思想に入れる | 知見が割れている |
| 名前 `tabiji`（単体） | npmに同名パッケージがあり、GitHubでも旅行関連で使われている |
| 名前の他候補: `rosenzu`、`hypodiff`、`pr-journey`、`shirube` | `pr-tabiji` を選択 |
