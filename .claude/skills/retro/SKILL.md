# retro

**同じ失敗と同じ手間を 2 回しない。** 作業の終わりに、この会話で起きたことから「次から楽になること」だけを拾い、その場でファイルに反映する。報告のための振り返りではない。

## いつ

- autopilot の**波の終わり**と区切りのレビューのとき (チェックリストに入っている)
- 1 つのタスクを終えて報告する直前 (小さいタスクなら 1 分で済ませる)
- ユーザーに**指摘・訂正・やり直し**を求められたとき (最優先で記録する)
- コンテキストの使用量が多くなってきたとき (圧縮の前に残す)

## 手順

1. **拾う** — この会話を見返し、当てはまるものだけを挙げる (無ければ「なし」で終わる):
   - **繰り返した手順**: 同じコマンド列・確認・調査を 2 回以上やった、または今後も繰り返す。
   - **詰まったこと・落とし穴**: エラーで 2 回以上やり直した、想定と違った挙動、権限で拒否された操作。
   - **トークンの無駄**: 大きなファイル・出力を丸ごと読んだ、同じファイルを何度も読んだ、不要な全件テスト、スクショの撮りすぎ、聞かなくてよい質問。
   - **ユーザーの好み・指摘**: 言われたこと (例: 「花吹雪は違和感」「幼すぎる」) と、その理由。
2. **置き場所を決める** — 下の表。迷ったら「一番近くで読まれる場所」。
3. **書く** — その場で反映する (後回しにしない)。1 項目 1〜3 行。日付と、何が起きたかを具体的に。
4. **汎用か判断する** — どのプロジェクトでも役立つなら、my-workflow に戻す (下の「my-workflow に戻す」)。
5. **一言で報告する** — 「retro: unity-verify に落とし穴 1 件、tips 1 件」のように。無ければ報告しない。

| 拾ったもの | 置き場所 |
| --- | --- |
| 繰り返した手順 (新しい種類) | 新しい skill `.claude/skills/<name>/SKILL.md` (下の「skill を作る基準」) |
| 繰り返した手順 (既存の skill の範囲) | その skill の手順を直す |
| 落とし穴・期待値の目安 | 関係する skill の「落とし穴」「プロジェクトでの記録」 |
| 進め方のルール・ユーザーの好み | `CLAUDE.md` (要点とリンクだけ) |
| 重大な判断 (技術選定・方針の転換) | `docs/07-decision-log.md` に 1 行 |
| トークン節約のコツ | `.claude/skills/retro/references/token-tips.md` |
| 止まっていること | `.claude/todo/progress.md` のブロッカー |

## skill を作る基準

- 作る: 2 回以上やった / 今後も確実に繰り返す / 手順を間違えると時間を失う (検証、リリース、データ移行、環境構築)。
- 作らない: 1 回きり、プロジェクトに関係ない、既存の skill の数行の追記で済む。
- 書き方: frontmatter の `description` に「何をするか」と「どんな依頼で使うか (言い回しの例)」を書く (これで呼ばれるかが決まる)。本文は手順・確認・落とし穴。長い参考資料は `references/` に分ける。
- 作ったら、名前と用途を一言でユーザーに報告する。

## my-workflow に戻す

どのプロジェクトでも役立つ改善 (汎用の手順、tips、テンプレートの不足) は、[my-workflow](https://github.com/NKMAK/my-workflow) にも反映する。

- my-workflow の場所が分かる (`.claude/my-workflow.lock` があり、手元に clone がある) なら、そこで Issue → ブランチ → PR を作る (autopilot と同じ流れ)。プロジェクト固有の名前・パス・値は外す。
- 時間がない・場所が分からないときは、`.claude/todo/workflow-feedback.md` に 1 行で残し、後でまとめて戻す。
- 戻したら、各プロジェクトでは `setup.sh --update` で取り込む。

## 落とし穴

- 振り返りを長く書かない。**直したファイルの差分が成果**であり、まとめの文章は要らない。
- 同じ内容を複数の場所に書かない。1 か所に書き、他からはリンクする。
- 一般論 (「テストを書こう」) は書かない。この会話で実際に起きたことだけ。
