# トークン節約の tips

実際に効いたものだけを足していく。1 行 1 項目。プロジェクト固有のものは末尾の「このプロジェクト」へ。

## 読む

- ファイルは必要な範囲だけ読む (`grep -n` で場所を見つけ、`sed -n 'A,Bp'` / Read の offset・limit)。大きなファイルを丸ごと読まない。
- 編集したファイルを確認のために読み直さない (Edit が失敗しなければ反映されている)。差分は `git diff --stat` から見る。
- 依存 (node_modules、Library、dist) やロックファイルを検索の対象から外す。
- 広い調査 (どこに何があるか分からない) だけサブエージェント (Explore) に任せ、結論だけ受け取る。場所が分かっている調査は自分でやる。

## 実行する

- テストは変えた範囲から流す (`jest <path>`、`playwright test <spec>`)。全件は PR の前に 1 回。
- 出力が長いコマンドは `| tail -n 20` や `grep` で絞る。成功時のログは要らない。
- 開発サーバーはバックグラウンドで起動し、出力のファイルは必要な行 (ポート) だけ読む。
- 一度で済む確認はまとめて 1 コマンドにする (`a && b && c`)。worktree の git だけは 1 コマンドずつ。

## ブラウザ・画像

- 操作は `browser_batch` でまとめる。確認は DOM のテキストを先に、スクショは要所だけ `scale: 0.4〜0.6` で。
- 一部を見たいときは `zoom` で範囲を切る (全画面を撮り直さない)。

## 会話・計画

- 既定値で決められることは聞かずに進め、記録だけ残す。質問はまとめて 1 回。
- 長い作業は `progress.md` に状態を書いてから進める (圧縮されても読み直しで済む)。
- 決まったことを何度も説明し直さない。
