# docs-index

docs が増えてもコンテキストを小さく保つ。**入口は `docs/index.md` 1 つ、各フォルダに `index.md`。** AI は index を読んで、必要なファイルだけを開く。

## 読むとき

1. `docs/index.md` の「作業別: まず読むもの」を見る。
2. 関係する分類の `index.md` を開き、「いつ読むか」が今の作業に当てはまるファイルだけを読む。
3. index の 1 行で足りるなら本文を開かない。長い参考資料 (出典・調査ログ) は確かめるときだけ。
4. 読んだのに使わなかった、または読むべきものが index から分からなかったら、その index の「いつ読むか」を直す (retro と同じ扱い)。

## 置き方

- **分類 (何について) でフォルダを切る。** 時系列や作業者では切らない。例: `concept/` (なぜ・何を目指すか)、`specs/` (要件)、`impl-plan/` (設計と計画)。
- docs 直下には、全体に効く少数のファイルだけ置く (`index.md`、`roadmap.md`、`decision-log.md`、`architecture.md`)。
- **index.md の表は「ファイル | 中身 (1 行) | いつ読むか」。** 「いつ読むか」が読む・読まないの判断材料なので、具体的な作業の場面で書く。
- 1 フォルダのファイルが 8 を超えたら、サブフォルダ (と index.md) に分ける。
- 1 ファイルは 1 テーマ。200 行を超えたら分ける候補。
- 番号の接頭辞 (`01-`) は、通読する順に意味があるフォルダだけで使う。
- リンクは相対パス。

## 足す・動かす・消すとき

1. ファイルを置く分類を決める (どれにも合わなければ、新しいフォルダを作り `docs/index.md` に行を足す)。
2. **同じコミットで**、そのフォルダの `index.md` (と必要なら `docs/index.md`、README) を直す。移動・改名は `git mv`。
3. 中のリンクを直す: `grep -rn '旧ファイル名' docs README.md CLAUDE.md .claude`。
4. チェックを通す: `.claude/skills/docs-index/check.sh` (index に載っていないファイルと、切れた相対リンクを出す。何も出なければ OK)。
